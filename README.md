# 福島，秋日慢行。2026

2026/10/13–10/24 的 12 天口袋行程。以使用者提供、更新於 2026/10/01 的 Markdown 為依據整理；沒有重新查核交通、開放時間、天候或個人訂位。

## 直接部署到 GitHub Pages

1. 解壓縮部署包，把裡面的檔案放到 repository 根目錄。`index.html` 必須直接位於你選擇發布的根目錄，不能只把 ZIP 上傳，也不要多包一層資料夾。
2. 在 repository 的 **Settings → Pages → Build and deployment**，將 **Source** 設成 **Deploy from a branch**，選擇 **main** 與 **/(root)**，按 **Save**。
3. 等待 GitHub 部署完成，使用 Pages 頁面提供的 HTTPS 網址開啟。無需 npm、建置工具、資料庫或 API key。

所有網站資源均使用相對路徑；個人首頁、`/<repository>/` 專案路徑與自訂網域都不需要改 BASE_URL。已附 `.nojekyll`。

也可選 `/docs` 發布：把整組網站檔案一起放進 `/docs`，再於 Pages 設定對應目錄。

### 檔案用途

| 檔案 | 用途 |
|---|---|
| `index.html` | 完整頁面、樣式、SVG 插圖、行程資料與互動程式，皆內嵌 |
| `sw.js` | HTTPS 網站的離線快取與版本更新 |
| `manifest.webmanifest` | 主畫面名稱、啟動路徑與圖示設定 |
| `icon.svg`、`icon-192.png`、`icon-512.png` | 網站／主畫面圖示 |
| `apple-touch-icon.png` | iPhone 主畫面圖示 |
| `.nojekyll` | 直接發布靜態檔案 |
| `README.md`、`TESTING.md` | 操作、維護與測試說明，可不公開部署 |

只要 `index.html` 就能使用主要行程介面。完整離線重新開啟網站、主畫面圖示與 App 模式需要其他檔案一起部署。直接從本機 `file://` 開 HTML 時，剪貼簿與本機儲存的支援依瀏覽器而異。

## 途中怎麼用

頁面有三個入口：**每日行程、待確認、旅途速查**。手機底部固定導覽；桌面使用頂部導覽。日期列可左右滑動；點 `D2 10/14` 之類的日期就切換。右上角準星回到此刻；「從早上」回到當日第一項。

首次開啟會把對應行程捲到固定日期列下方。之前的行程仍完整存在，上滑即可回看；旅行封面與當日住宿、備案備註也在上方。手機版的導航與複製按鈕加大，並支援安全區、橫向畫面及 reduced-motion 偏好。

### 日期與時區規則

- 讀取裝置的當前時間，以及 `Intl.DateTimeFormat().resolvedOptions().timeZone` 回報的時區。頁首顯示日本時間；裝置非日本時区時，也顯示裝置時間。
- **旅行日以日本日曆日期判定**，日本境內活動一律用 `Asia/Tokyo / UTC+9` 對應實際時間。不是把台灣顯示的「09:45」直接套到日本「09:45」行程。
- 航班分別保留兩端時區：D1 10:30 台灣出發、14:30 日本抵達；D12 18:00 日本出發、21:00 台灣抵達。內部使用明確的 `+08:00 / +09:00` 時間戳比較。
- 例如日本 2026/10/14 09:45，定位在 **09:40–10:00 藥師岳展望台、紅葉攝影**。同一瞬間台灣是 08:45；台灣 09:45 則對應日本 10:45，應定位在前往山頂的時段。
- 旅行前、旅行後，或年份不是 2026，一律預設 **D1 第一項**；不會因上次看過 D12 就在下次開啟時停在 D12。勾選與備案選擇才會保存。
- 時段空檔定位到下一項；日程全部結束後停在最後一項並提示結束。只有「晚間」等未定時活動保留原字樣，不虛構可供旅客採信的精確時刻；內部僅依前後順序做捲動定位。
- 網頁每 30 秒更新時間標示，不會在你閱讀途中一直自動拉動捲軸。點準星即可重新定位。裝置的日期、時間與時區需要設定正確。

### 出發前就能測試

在 **旅途速查 → 預覽指定日期時間**，選擇 `2026-10-14`、`09:45`、`日本 UTC+9`，按「預覽這一刻」。

此模式不更改裝置時鐘，預覽時間固定不走動。頂部時鐘會持續顯示「預覽」，可直接點「結束預覽」回到真實時間。也支援明確的 `preview` 查詢參數供測試；使用前務必確認不是把測試連結當作日常入口。

### 待確認與勾選

保留原文件 **31 組事項**：P01、P03–P32；原文件沒有 P02，不新增虛構項目。P17 額外拆成四個可獨立勾選的里程碑：あいづ座位、只見線兩張票、雙葉跨區票、已付款新幹線領票。

明確預約期限先顯示，其餘重點依處理日期排列。「官方截止」「建議」「複核」「選案時間」分開標示；只有原文件提供的明確時刻才當作時刻比較。日期已過，不等於真的沒有預約或已取消。已成立的租車與參訪仍標為已預約，僅核對剩餘事項。

勾選與方案存在本機 `localStorage`，不會自動在電腦與 iPhone 同步。可在「旅途速查 → 備份勾選與方案」匯出 JSON，再到另一台裝置匯入。匯入會取代當前勾選與方案；私人租車編號不包含在備份裡。清除瀏覽器資料會清除勾選；Safari 與主畫面 App 的儲存行為請以實際裝置為準。

## Google Maps 不需 API key

這份頁面使用 **Google Maps URLs**，不是 Places API、Maps JavaScript API 或內嵌動態地圖，因此不需要申請或購買 API key。

- 明確的一般地點：**導航**開啟到目的地的方向服務。
- 列車／巴士：**路線**帶入起終點；Google Maps 產生的路線不保證等於原文件的指定班次。
- 山區、尚待確認的人行入口：**地圖**只查位置，不把一般導航當作已確認的登山／夜間安全路線。
- 多個候選地點：先開地點選單，例如富岡漁港海側與富岡公園山側，不暗中替旅客選定一個。
- 複製按鈕：複製日文搜尋文字。剪貼簿被拒絕時，會顯示可以長按手動複製的文字，不假裝複製成功。

日文名稱與地區字樣作為搜尋條件，並保留文件提供的住宿 Google Maps 連結；沒有另外向 Places API 取得 Place ID，也沒有對所有入口逐一完成導航驗證。使用前確認地圖辨識到正確地點，集合與取還車點優先依私人訂單。

Google Maps App 已安裝時可由系統開啟 App；實際開啟 App、路線預覽或逐步導航取決於裝置設定、權限、起點與 Maps 支援情況。

## iPhone 主畫面與離線

以 Safari 開啟部署後的 HTTPS 網址，從「分享」選「加入主畫面」。依 Safari 的分頁版型，分享可能位於頁面選單內。

完整部署後，先連網開啟一次，等頁尾顯示 **已備妥離線行程**，再測試飛航模式與重新開啟。離線可讀已快取行程與操作本機勾選；Google Maps、參考官網與即時資訊不是本頁的離線內容。瀏覽器可能回收快取，故仍應另留票券、訂單與重要路線的私人離線副本。

Service Worker 只快取本網站檔案，不攔截 Google Maps 或其他官網。連網重新開啟時優先取得新 HTML；網路失敗或超過 3.5 秒時可退回已有快取。HTTPS 是正式環境的必要條件，本機開發可用 localhost。

## 公開部署與隱私

**本版不嵌入原文件的租車貸渡編號，也沒有附上原始私人 Markdown。**「旅途速查 → 私人租車編號」可自行貼入，僅存本機、不送出、不匯出，但不是加密保管。

住宿、日期、班次與座位資訊仍包含在公開 HTML。GitHub Pages 發布成網站後，不能把「repository 設成 private」當作這個網站已有登入保護。`noindex` 也只是搜尋索引偏好，不是存取控制。不要再把護照、票券 QR code、完整訂單與私人行程原稿一起上傳。

## 更新行程

這份 HTML 是目前 Markdown 的**整理快照**，不會自動重新讀取之後修改的 `.md`。

`index.html` 內的 `<script id="trip-data" type="application/json">` 保存結構化資料：

- `days`：每日事件、備案、原文與收合備註。
- `places`：日文搜尋文字、原始地圖連結與導航類型。
- `tasks`：待確認項目、期限性質、完整原文、獨立勾選里程碑。
- `contacts`、`hotels`：聯絡方式與住宿速查。

維護時保持 JSON 合法。若改動活動時間，請同步更新 `time` 顯示文字及 `start`／`end`；時間欄一律用 `HH:mm`，航班例外需保留 `startOffset`、`endOffset`。事件及待辦 ID 影響已儲存的勾選與測試，不要無意更名。

發布新版時也把 `sw.js` 的 `VERSION` 改成新的字串；本網站的舊版本快取才會被定向清理。頁面沒有 npm 相依、外部字型或第三方 JavaScript。
